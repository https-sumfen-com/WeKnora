# 数据来源与 SONO-MCP 取数

## 总规则

企业、基地、地块、设备、农机的事实数据必须来自 SONO-MCP 或当前任务内明确可追溯的数据源。Agent 可以总结、对比、排序、解释和生成建议，但不能用模型常识补运营事实。

如果用户要求生成详情分析、趋势判断、风险诊断、作业复盘或报告，而当前上下文没有足够数据，先调用 SONO-MCP 读取对应对象和指标。普通问答走自然回复；当用户要求局部结构化展示，或数据本身存在异常、风险、预警、离线、缺口、阈值越界等需要局部高亮的情况时，可以组装 card / quick-reply。只有明确报告意图才组装 report。

## 允许来源

- 当前任务中读取到的 SONO-MCP 资源、工具或 connector 结果。
- 后端/API 直接给到 Agent 的 payload。
- 当前会话工具输出。
- 用户在当前问题中明确给出的事实。
- 用户要求延续历史回答时，已经归一化并可追溯的历史消息或 blocks。

## 禁止来源

- 凭经验估算企业产量、基地面积、地块墒情、设备在线状态、农机作业时长。
- 为了让图表完整而补坐标、时间点、阈值、病虫害等级、预警数量或任务结果。
- 在生产回答中复用 demo fixture，除非用户明确要求 mock/demo 输出。
- 把用户的提问意图当作已验证数据。

## 取数顺序

1. 先识别范围和对象 ID: 企业、基地、地块、设备、农机。
2. 读取对象快照: 名称、归属、状态、位置、面积、在线状态、当前任务等。
3. 读取明细数据: 指标序列、告警、作业记录、设备遥测、农机轨迹、地块历史、报告指标。
   - 地块情况/地块分析/地块报告：若已有 `cid` 和 `plot_id`，优先读取 `get_wofost_report`，再按需要读取 `get_plot_info` 基础快照。
4. 需要报告时读取可聚合数据: 同企业下基地汇总、同基地下地块/设备/农机列表、时间范围内趋势和异常。
5. 命中结构化渲染意图，或读取到异常、风险、预警、离线、缺口、阈值越界等需要局部高亮的数据时，可以生成 block；数据不足时不生成占位 block，缺口交由自然回复说明。

## 分析对象与基础数据

| 对象 | 生成分析前优先读取 |
| --- | --- |
| 企业 | 企业档案、基地列表、地块/设备/农机汇总、关键经营指标、近期风险和作业概况 |
| 基地 | 基地档案、边界或中心点、地块列表、设备列表、农机列表、作物或生产周期、近期告警和作业 |
| 地块 | WOFOST 模型报告、生育进程、模拟产量/生物量、水分/养分平衡、地块档案、面积、种植信息、墒情/长势序列、作业记录、风险阈值 |
| 设备 | 设备档案、归属基地/地块、在线状态、最新遥测、历史序列、告警、控制或任务结果 |
| 农机 | 农机档案、归属、当前位置、在线/作业状态、任务记录、轨迹、维护或油耗信息 |

## Card 数据来源

生成每张卡片前先确认来源类型:

```txt
metric: SONO-MCP/API 数值快照或聚合结果
chart: SONO-MCP/API 时间序列、分类序列、对比序列、WOFOST 日序列、关系、流向、空间或多维指标
table: SONO-MCP/API 行数据
map: SONO-MCP/API 坐标、中心点、边界、轨迹或图层
recommendation: SONO-MCP/API 事实 + 明确规则、模型、工具或业务阈值
retrospect: SONO-MCP/API 作业历史、告警历史、变更记录或已归一化历史块
phase-summary: SONO-MCP/API 生产阶段摘要、报告历史或阶段指标
```

如果某张卡片的必需字段缺失，不要输出该卡片。可以由自然回复说明为什么缺失。

## Chart vs Table 优先级

优先判断能否生成 `chart`。以下数据形态默认先走 ECharts:

- 时间序列: 天气预报、墒情变化、产量趋势、设备遥测变化、作业进度。
- WOFOST 模型序列: DVS、LAI、TAGP、WSO、SM、TRA、RD、NuptakeTotal 等生长模拟趋势。
- 分类对比: 作物面积、地块类型、设备状态分布、风险等级数量。
- 占比结构: 种植结构、地块类型结构、设备在线/离线占比。
- 多指标对比: 积温/积雨同比、传感器多指标、长势评级、基地横向对比。
- 空间或路径: 坐标点、边界、轨迹、作业路线。

只有当数据主要是明细清单、审计记录、编号状态、逐行文本字段，或前端需要逐行操作时，才用 `table`。不要因为原始 API 返回数组就默认生成 table。

## 缺口表达

用自然回复写清楚缺什么、影响什么、下一步需要补什么:

```md
## 数据缺口

当前 SONO-MCP 没有返回 B-07 地块近 14 天墒情序列，因此不能生成墒情趋势图。已基于最新墒情快照给出风险判断；如需趋势图，需要补充 `soil_moisture_daily` 数据。
```

不要生成占位图表、占位地图或虚构指标。

地块情况类问题如果缺少 `cid` 或 `plot_id` 导致无法读取 WOFOST 报告，应说明“缺少 WOFOST 报告所需的 cid/plot_id，因此不能生成作物模型模拟分析”，不要用普通地块基础信息冒充模型报告。

## 自检

- 每个数字都能追溯到 SONO-MCP、API、工具输出或用户明确事实吗？
- 每个对象 ID、坐标、边界、任务结果都有来源吗？
- 数字和单位是否分离？
- 是否误用了 demo/mock 数据？
- 数据不足时是否用自然回复说明，而不是补一张假 card？
- 地块情况/地块分析是否优先检查了 WOFOST 报告来源，而不是只输出地块基础快照？
