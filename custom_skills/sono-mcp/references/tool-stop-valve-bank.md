# stop_valve_bank 参数与返回处理规则

停止指定阀门组。这是会改变设备状态的写操作，只能在用户明确要求关闭且阀门组唯一确定时调用。

## 请求参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 阀门组 ID，必须为正整数；可取选中的 `get_valve_bank_by_device.payload[].id` |
| `cid` | 否 | 企业 ID；当前服务层不强制，但上下文有值时一并传入 |
| `token` | 否 | 会话中的上游访问令牌；没有时省略，禁止编造 |
| `entity_id` | 否 | 实体 ID；没有时省略 |
| `entity_info_id` | 否 | 实体信息 ID；没有时省略 |
| `auto_off_minutes` | 否，不应传 | 启动专用参数；停止逻辑不会使用该字段 |

所有数字参数支持 JSON 整数或整数字符串。跨前端/JSON 可信草稿传递 `cid` 和 `id` 时优先使用十进制字符串，避免 int64 经 JavaScript Number 丢失精度。`id` 是阀门组 ID，不是 `plot_device_id` 或设备 `device.id`。

推荐调用：

```json
{
  "cid": "2007",
  "id": "31"
}
```

若上下文确实没有企业 ID，当前服务层的最小调用为：

```json
{
  "id": "31"
}
```

缺少有效 `id` 时返回参数错误，不会执行关闭。

## 调用约束

- 用户只查询阀门组、运行状态或灌溉知识时不得调用。
- 不得仅因查询到阀门组或看到运行状态就自动关闭；必须有用户明确的停止/关闭意图。
- 用户指定多个阀门组、名称存在歧义或缺少唯一 `id` 时先追问。
- 不要传 `auto_off_minutes`，也不要在关闭后默认追加状态查询。

## 返回结构与输出

成功响应是上游 JSON 的原样透传，当前没有固定业务字段 schema，可能是对象、布尔值或其他 JSON 值。单元测试使用的 `{"ok":true}` 仅是测试夹具，不应视为生产字段契约。

- 非空响应：完整保留上游已有字段；只有响应明确表示成功时才回答“阀门组关闭成功”。
- 空对象、`null` 或空文本：回答“控制请求已发送，但上游未返回可确认的结果”，不要声称设备已经实际关闭。
- `isError=true`：明确说明关闭失败，不要自动重试或调用其他控制工具。
