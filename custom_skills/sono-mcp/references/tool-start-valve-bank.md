# start_valve_bank 参数与返回处理规则

启动指定阀门组。这是会改变设备状态的写操作，只能在用户明确要求启动且阀门组唯一确定时调用。

## 请求参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `cid` | 是 | 企业 ID，必须为正整数 |
| `id` | 是 | 阀门组 ID，必须为正整数；可取选中的 `get_valve_bank_by_device.payload[].id` |
| `auto_off_minutes` | 否 | 自动关闭等待分钟数；只传用户明确指定的正整数 |
| `token` | 否 | 会话中的上游访问令牌；没有时省略，禁止编造 |
| `entity_id` | 否 | 实体 ID；没有时省略 |
| `entity_info_id` | 否 | 实体信息 ID；没有时省略 |

所有数字参数支持 JSON 整数或整数字符串。`id` 是阀门组 ID，不是 `plot_device_id` 或设备 `device.id`。`auto_off_minutes` 未指定或为 `0` 时不发送该字段；不得替用户设定默认时长。

立即启动示例：

```json
{
  "cid": 2007,
  "id": 31
}
```

启动并请求 10 分钟后自动关闭：

```json
{
  "cid": 2007,
  "id": 31,
  "auto_off_minutes": 10
}
```

缺少有效 `cid` 或 `id` 时返回参数错误，不会执行启动。

## 调用约束

- 用户只查询阀门组、运行状态或灌溉知识时不得调用。
- 不得仅因 `get_valve_bank_by_device` 返回了阀门组就自动启动；查询结果不是控制授权。
- 用户指定多个阀门组、名称存在歧义或缺少唯一 `id` 时先追问。
- 不得把 `run_status` 自行解释成启动指令。

## 返回结构与输出

成功响应是上游 JSON 的原样透传，当前没有固定业务字段 schema，可能是对象、布尔值或其他 JSON 值。单元测试使用的 `{"ok":true}` 仅是测试夹具，不应视为生产字段契约。

- 非空响应：完整保留上游已有字段；只有响应明确表示成功时才回答“阀门组启动成功”。
- 空对象、`null` 或空文本：回答“控制请求已发送，但上游未返回可确认的结果”，不要声称设备已经实际开启。
- `isError=true`：明确说明启动失败，不要继续调用停止或查询工具作为补偿。
