# WeKnora 上线流程

> 对应分支：`feat/iframe-auto-login`（合并 main 后流程相同）  
> 适用场景：把 WeKnora 作为 iframe 嵌入外部业务系统（农业科研定位 · 天工智农品牌）

---

## Step 1 · 拉代码

```bash
git clone https://github.com/https-sumfen-com/WeKnora.git
cd WeKnora
git checkout feat/iframe-auto-login    # 或合并到 main 后再 checkout main
```

## Step 2 · 配置 `.env`

```bash
cp .env.example .env
vim .env
```

至少填以下变量（其他用默认即可）：

```bash
# === 数据库 / 基础设施 ===
DB_HOST=postgres
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=<生产 DB 密码>
DB_NAME=WeKnora
REDIS_ADDR=redis:6379
RETRIEVE_DRIVER=postgres
STORAGE_TYPE=minio                       # 或 local / cos / s3 / oss
DOCREADER_ADDR=docreader:50051

# === 加密密钥（必须，一旦设定不要改）===
SYSTEM_AES_KEY=<openssl rand -hex 32>    # 加密 iframe_secret + model api_key
JWT_SECRET=<随机字符串>                  # 签 JWT

# === 阿里云 DashScope ===
WEKNORA_ALIYUN_API_KEY=sk-xxxxxxxx       # 4 个内置模型共用

# === iframe 嵌入（启用自动 provision）===
WEKNORA_IFRAME_MASTER_SECRET=<openssl rand -hex 32>
# 同一把 key 通过带外渠道告知所有外部业务系统的后端

# === 父域名白名单（可选）===
WEKNORA_FRAME_ANCESTORS=https://your-parent-system.com

# === 锁死注册（生产必须）===
DISABLE_REGISTRATION=true
GIN_MODE=release
```

> ⚠️ `SYSTEM_AES_KEY` 和 `WEKNORA_IFRAME_MASTER_SECRET` 一旦泄漏需立即轮换；生成后请妥善保存到密钥管理系统。

## Step 3 · 启动服务

```bash
make build-images       # 构建 backend / frontend / docreader 镜像
docker compose up -d
docker compose logs -f app
```

等到日志出现：
```
Database is up to date (version: 36)
[Container] Container initialization completed successfully
Server is running at 0.0.0.0:8080
```

**自动完成（配置随镜像走，无需手动）**：
- 数据库迁移到 36（iframe schema + organization 字段 + iframe_nonces 表）
- 加载 `config/builtin_agents.yaml` —— 三个天工智农内置 agent
- 加载 `config/prompt_templates/*.yaml` —— 系统时间强制声明 + 农业科研定位
- iframe 嵌入模式 UI 隐藏 logo / 外链 / 退出按钮

## Step 4 · 一次性数据初始化

构建运维 CLI 并塞入 4 个内置模型：

```bash
make build-admin

./weknora-admin model add-builtin --id builtin-llm-default       --type KnowledgeQA --provider aliyun --name qwen3.6-plus
./weknora-admin model add-builtin --id builtin-embedding-default --type Embedding   --provider aliyun --name text-embedding-v4 --dimension 1024
./weknora-admin model add-builtin --id builtin-rerank-default    --type Rerank      --provider aliyun --name qwen3-vl-rerank
./weknora-admin model add-builtin --id builtin-vlm-default       --type VLLM        --provider aliyun --name qwen-vl-max --supports-vision

./weknora-admin model list   # 验证 4 行 is_builtin=true source=remote
```

> **ID 不能错**——`builtin_agents.yaml` 写死引用这 4 个 ID（KB / VLM / rerank 也写死）。  
> Rerank 自动用 DashScope 原生 endpoint（CLI 已处理），不会误用 compatible-mode/v1 导致 404。

## Step 5 · 外部业务系统接入

运维通过带外渠道把 `WEKNORA_IFRAME_MASTER_SECRET` 告知外部系统后端开发。**不要进前端代码**。

外部后端用以下示例（以 PHP 为例）生成 iframe URL：

```php
$weknora = new WeKnoraIframe(
    masterSecret: $_ENV['WEKNORA_IFRAME_MASTER_SECRET'],
    baseUrl:      $_ENV['WEKNORA_BASE_URL'],
);

$url = $weknora->buildUrl(
    cid:    $user->organization_id,        // 业务组织 ID（稳定，可任意字符串）
    cName:  $user->organization_name,      // "ABC 公司"，作为 Org 显示名
    mobile: $user->phone,                  // 11 位手机号
    role:   $user->isAdmin ? 'admin' : 'editor',  // admin / editor / viewer
);
// 渲染 <iframe src="..." width="100%" height="100%">
```

Python / Node / Go / TS 同样的模式（HMAC-SHA256 派生 + 签名），见 `docs/iframe-integration.md`。

**首次使用某 cid 时 WeKnora 自动**：
- 创建 Organization（名字 = c_name）
- 创建当前 mobile 的 personal Tenant + User
- 把用户加入 org（角色 = URL 的 role）
- **自动建一个共享知识库**：`{c_name}共享知识库`，绑定 builtin 4 模型 + Local 存储 + AI 问题生成开启
- 共享 KB 给整个 org（editor 权限）

后续 cid 不变的不同 mobile → 加入同一 org，看到同一共享 KB；mobile 不同的 user 之间数据**完全隔离**（对话 / 个人 KB），共享空间内容互通。

## 📋 日常运维

| 操作 | 命令 |
|---|---|
| 新外部组织接入 | ✅ 自动（用户走 URL 即可，零运维介入） |
| 某 cid 怀疑泄漏 | `./weknora-admin iframe rotate --cid X` |
| 禁用某 cid | `./weknora-admin iframe revoke --cid X`（org 行保留，但拒绝再登录） |
| Master secret 全面轮换 | 改 `.env` → `docker compose restart app` → 通知所有外部系统同步更新 master |
| 改 agent / prompt 配置 | 改 yaml → `docker compose restart app` →（如 tenant 已 override）`DELETE FROM custom_agents WHERE id LIKE 'builtin-%'` |
| 加新内置模型 | `./weknora-admin model add-builtin --id ... --type ... --provider ... --name ...` |

## ⚠️ 已知边界

1. **共享 KB 跟首个 user 走**：自动建的 KB 在首位登录 user 的 personal tenant 下；若该 user 被删 → tenant 被删 → KB 跟着没。WeKnora 现有架构限制
2. **并发首登可能建多个 KB**：两个 user 同时首次登入同一全新 cid → 都看到 `CountMembers==1` → 各建一个。生产概率极低，目前只 log 不拦截
3. **`tenants.web_search_config` 仍是旧字段**：UI 配置走 `web_search_providers` 表，agent 工具已加 fallback；后端 tenant 弹窗如果显示"未配置"是字段命名遗留问题
4. **模型源数据须 source='remote'**：CLI 已修；如手动 SQL INSERT 别误填 'aliyun' 等 provider 名作为 source
